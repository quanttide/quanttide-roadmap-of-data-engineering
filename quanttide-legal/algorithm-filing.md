# 合规材料即数据集生产

**来源**：2026-10-09 对话整理（对话原文见 git 历史）  
**状态**：设计要点，未实施。文中提及的外部方案文档（服务登记材料框架 08 号）未随迁，待定位。

核心判断：备案登记里最硬的两块——拦截关键词库与评估测试题库——本质上都是数据集需求。按数据集需求定义它们，数据云可以直接当生产工具使用，而不是法务与运营手工攒。

## 设计要点

把合规翻译成数据集需求规格：

- 数据集 A，拦截关键词库：字段为风险类别、关键词、变体（同音、拼音、拆字）、来源、日期、版本；量纲与覆盖类别按属地要求与 GB/T 45654-2025 确定，月度更新，台账留存。
- 数据集 B，评估测试题库：字段为类别、提示词、模型原始输出、期望动作、安全研判、独立验证人、是否有效题；量纲按国标硬指标分生成、拒答、非拒答三类，每题保留「提示词 + 原始输出 + 研判」三联记录，覆盖多轮对话、提示注入与隐喻对抗。

五层生成流水线：需求建模 → 取数编排（接开源词库、在线工具与业务源；测试题库用提示词模板调度真实服务抓取输出）→ 质量校验门 → 版本台账 → 交付封装。测试题库「用真实服务跑」的硬要求正好由调度能力满足。

复用逻辑：一次性动作变成可复用的数据产品——月度更新、年度审计、换基座变更都是重跑数据集；每条数据带溯源与版本，对应审核「真实、量够、类全、要更新」四问。

人工边界：取数、去重、分类、变体生成、跑测抓输出可全自动；安全研判与独立团队验证不能全自动——法规要求人担责，只能机器辅助加人工把关。

## 下一步切口
